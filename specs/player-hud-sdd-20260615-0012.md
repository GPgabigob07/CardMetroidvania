# Player HUD SDD - 20260615-0012

## Contexto

This specification defines the first implementation-ready player HUD baseline.
It exists to translate the approved visual blockout into a compact Unity uGUI
layout without treating temporary artwork as final art direction.

## Goals

- Show player health as exactly five discrete chevrons in the prototype.
- Show energy with exactly 30 normalized segments and an exact whole-number
  value beside the bar.
- Show Card Time availability as one card for Neutral, two for Chain, and three
  for Finisher.
- Keep both corner clusters compact and inside a 32 px safe margin at the
  `1920 x 1080` reference resolution.
- Keep HUD code observational. It must not mutate health, energy, combo state,
  or Card Time.
- Make placeholder art independently replaceable through Sprite references.

## Technology Decision

Use Unity uGUI because the baseline is image-driven, small, and already depends
on `com.unity.ugui`. The root Canvas uses:

- `Screen Space - Overlay`;
- `Canvas Scaler / Scale With Screen Size`;
- reference resolution `1920 x 1080`;
- match width or height `0.5`;
- sorting order `100`;
- no raycaster because the HUD is non-interactive.

## Layout

### Top Left

Anchor the cluster to the top-left corner at `(32, -32)`.

Health:

- exactly five right-pointing chevrons;
- one chevron equals one health point;
- 22 x 16 px per chevron;
- 4 px gap;
- filled crimson `#E81F16`;
- empty dark red with reduced opacity;
- no diamond, jewel, heart, or square silhouette.

Energy:

- positioned 8 px below health;
- small cyan lightning icon at the left;
- exactly 30 segments;
- 5 x 14 px per segment;
- 2 px gap;
- fixed visual capacity independent from numeric maximum;
- exact current value on the right;
- whole values use floor formatting to avoid rapid decimal noise.

The segment fill count is:

`ceil(clamp01(current / maximum) * 30)`

The numeric value remains authoritative for exact reading.

### Bottom Right

Anchor the cluster to the bottom-right corner at `(-32, 32)`.

- exactly three authored card frames;
- cards overlap in a compact upward-left fan;
- hidden when Card Time is unavailable;
- Neutral reveals one card;
- Chain reveals two cards;
- Finisher reveals three cards;
- available cards use subdued cyan;
- an active Card Time session uses bright cyan;
- the cluster must remain fully inside the safe margin.

The cards indicate combo tier, not three independently selectable abilities.

## Runtime Ownership

`PlayerHudUI` observes:

- `SimpleHealth.Changed`;
- `PlayerResourceWallet.Changed`;
- the configured Energy `ResourceDefinitionSO`.

`CardTimeHudUI` implements `IGameplayServicesConsumer` and observes:

- `IGameplayServices.CardTime.Current`;
- `CardTimeSessionEventChannelSO`.

The HUD never receives a Card Time source token and exposes no gameplay command.

## Setup Workflow

Use the idempotent Editor command:

`TIC/Setup/Create Or Update Sample Scene HUD`

The command:

1. opens `Assets/Scenes/SampleScene.unity`;
2. finds the existing player;
3. adds `SimpleHealth` if absent;
4. loads the existing Energy resource;
5. rebuilds one generated `[Player HUD]` Canvas;
6. wires all health, energy, and Card Time references;
7. saves the scene.

Running the command twice must replace the generated HUD instead of creating a
duplicate. Artist-authored final HUD work should move out of the generated root
before rerunning the baseline setup command.

## Acceptance Criteria

- five and only five health chevrons exist;
- health artwork does not form a diamond silhouette;
- 30 and only 30 energy segments exist;
- the energy number updates from `PlayerResourceWallet`;
- health updates from `SimpleHealth`;
- Card Time reveals 1, 2, or 3 cards for Neutral, Chain, or Finisher;
- active Card Time presentation remains readable while gameplay time is scaled;
- no HUD code changes gameplay state;
- both clusters remain inside safe margins at 16:9;
- no additional package is required;
- display math has EditMode coverage.
